# 米灵 Android 视觉与交互规范

> 状态：主视觉基线  
> 适用范围：米灵 Android App 的登录、验证码、AI 对话、钱包、转账、账单、支付确认、会话抽屉和个人中心  
> 技术栈：Kotlin + Jetpack Compose + Material 3  
> 视觉基准：已选定的“纯对话优先”米灵首页方案

## 1. 设计定位

米灵是一款以 AI 对话为主入口的智能支付与生活助手。界面需要同时表达：

- **轻盈**：大面积留白，减少传统金融 App 的信息堆叠。
- **智能**：使用克制的蓝紫渐变、米灵形象和流式反馈表达 AI 感。
- **可信**：金额、支付状态和确认操作必须清晰、稳定、高对比。
- **友好**：使用自然中文、圆角卡片和可执行建议降低操作门槛。
- **受控**：AI 可以建议和准备操作，但支付、转账必须由用户明确确认。

整体风格定义为：

> 浅色、极简、对话优先、强留白、细描边、大圆角、轻阴影、蓝紫 AI 品牌点缀。

不得照搬第三方产品的 Logo、头像、品牌名称、文案或专属图标。

## 2. 视觉原则

### 2.1 单一视觉焦点

每个页面只保留一个最主要的视觉焦点：

- 首页焦点是“米灵身份 + 推荐问题”。
- 对话页焦点是当前消息和业务卡片。
- 转账页焦点是收款人、金额和确认动作。
- 结果页焦点是交易状态。

不要在同一首屏同时展示大余额、多个统计图、活动广告和大量导航入口。

### 2.2 留白优先

- 页面背景以纯白为主。
- 内容之间使用空间区分层级，避免依赖粗分割线。
- 首屏中部允许保留较大空白，强化米灵形象和对话入口。
- 不为了“填满页面”而增加无业务价值的卡片。

### 2.3 业务真相优先

- 金额、余额、订单和交易状态只能使用后端返回值。
- 颜色不得成为状态的唯一表达，必须同时提供图标或文字。
- “处理中”不能使用成功样式，也不能提供重复提交入口。
- AI 生成内容与权威业务结果必须在视觉上明确区分。

## 3. 颜色系统

颜色必须通过 Compose Theme Token 使用，业务组件不得散落硬编码色值。

| `MilingSurface` | `#FFFFFF` | 卡片、输入框、弹层 |
| `MilingSurfaceSubtle` | `#F7F9FC` | 次级区域、轻量分组背景 |
| `MilingSurfaceBlue` | `#F2F6FF` | AI/支付提示、选中状态背景 |
| `MilingTextPrimary` | `#111318` | 标题、正文、金额 |
| `MilingTextSecondary` | `#667085` | 副标题、说明文字 |
| `MilingTextMuted` | `#8E96A3` | 占位符、时间、非关键标签 |
| `MilingBorder` | `#DCE3EE` | 默认卡片和控件描边 |
| `MilingDivider` | `#EEF1F5` | 设置列表内部弱分割线 |
| `MilingIconPrimary` | `#111318` | 主要线性图标 |
| `MilingIconSecondary` | `#7C8594` | 次级图标、箭头 |

### 3.2 品牌颜色

| Token | 色值 | 用途 |
|---|---:|---|
| `MilingPrimary` | `#1677FF` | 主操作、焦点、品牌图标 |
| `MilingPrimaryPressed` | `#0958D9` | 主操作按下状态 |
| `MilingPrimarySoft` | `#EAF3FF` | 主色浅背景 |
| `MilingLilac` | `#8B6DFF` | 米灵形象、AI 身份辅助色 |
| `MilingLilacSoft` | `#F1EDFF` | AI 卡片浅背景 |

### 3.3 米灵渐变

渐变只用于米灵形象、AI 标题或极少量品牌装饰，不用于大面积页面背景。

```text
MilingGradient:
  start  #2F80FF
  middle #5D72FF
  end    #9A6BFF
  angle  0° 或从左到右
```

限制：

- 单屏最多出现两个渐变元素。
- 金额、按钮正文、交易状态不得使用渐变文字。
- 渐变标题下必须保留足够对比，不能影响可读性。

### 3.4 语义颜色

| Token | 色值 | 用途 |
|---|---:|---|
| `MilingSuccess` | `#16A34A` | 成功、已完成 |
| `MilingSuccessSoft` | `#ECFDF3` | 成功状态背景 |
| `MilingWarning` | `#D97706` | 待确认、风险提示 |
| `MilingWarningSoft` | `#FFF7E6` | 警告状态背景 |
| `MilingError` | `#DC2626` | 失败、危险操作、字段错误 |
| `MilingErrorSoft` | `#FEF2F2` | 错误状态背景 |
| `MilingProcessing` | `#2563EB` | 处理中 |
| `MilingProcessingSoft` | `#EFF6FF` | 处理中背景 |

正文文字与背景的对比度不得低于 `4.5:1`；大号文字不得低于 `3:1`。

## 4. 字体系统

### 4.1 字体族

默认使用 Android 系统无衬线字体：

```text
sans-serif
```

中文由系统匹配 Noto Sans CJK/设备默认中文字体。首版不额外内置第三方字体，避免包体、授权和不同设备渲染问题。

规则：

- 中文、数字和英文使用同一系统字体体系。
- 不使用手写体、衬线体或装饰字体展示金额和支付状态。
- 字重只使用 `Regular / Medium / SemiBold / Bold`。
- 金额优先启用等宽数字特性；无法启用时保持数字基线和字距稳定。

### 4.2 字体层级

| Compose Token | 字号/行高 | 字重 | 用途 |
|---|---:|---|---|
| `displayLarge` | `42sp / 50sp` | Bold | 首页“我是米灵” |
| `headlineLarge` | `32sp / 40sp` | Bold | 金额、结果状态 |
| `headlineMedium` | `26sp / 34sp` | SemiBold | 页面核心标题 |
| `titleLarge` | `22sp / 30sp` | SemiBold | 顶部标题、弹窗标题 |
| `titleMedium` | `18sp / 26sp` | Medium | 卡片标题、列表主文案 |
| `bodyLarge` | `17sp / 26sp` | Regular | 对话正文、表单主要内容 |
| `bodyMedium` | `15sp / 23sp` | Regular | 常规说明、列表副文案 |
| `labelLarge` | `15sp / 20sp` | Medium | 按钮、快捷入口 |
| `labelMedium` | `13sp / 18sp` | Medium | 状态标签、安全提示 |
| `bodySmall` | `12sp / 17sp` | Regular | 时间、辅助说明 |

### 4.3 字体使用要求

- 正文原则上不得小于 `15sp`。
- 支付安全、错误和结果说明不得小于 `14sp`。
- 主金额推荐 `32–40sp`、Bold。
- 最多连续使用两种字重，避免整页大量粗体。
- 支持系统字体缩放；在 `1.3x` 字体比例下不得截断关键信息。
- 长标题最多两行；金额、状态和主按钮文案不得省略。

## 5. 间距系统

使用 `4dp` 为最小单位、`8dp` 为主要基线。

| Token | 数值 | 用途 |
|---|---:|---|
| `space1` | `4dp` | 图标内部微间距 |
| `space2` | `8dp` | 紧密元素 |
| `space3` | `12dp` | 图标与文字 |
| `space4` | `16dp` | 组件内部标准间距 |
| `space5` | `20dp` | 页面水平内边距 |
| `space6` | `24dp` | 卡片分组、主要内容间距 |
| `space8` | `32dp` | 模块间距 |
| `space10` | `40dp` | 大模块分隔 |
| `space12` | `48dp` | 页面章节分隔 |
| `space16` | `64dp` | 首页大留白 |
| `space20` | `80dp` | Hero 区域留白 |

### 5.1 页面间距

- 手机页面水平边距：`20dp`。
- 大屏/折叠屏内容最大宽度：`600dp`，水平居中。
- 顶部栏内容高度：`56dp`，另加系统状态栏 Insets。
- 底部悬浮输入框距离安全区：`12dp`。
- 固定底部输入区上方必须为列表预留空间，内容不得被遮挡。

## 6. 圆角、描边和阴影

### 6.1 圆角

| Token | 数值 | 用途 |
|---|---:|---|
| `radiusSmall` | `10dp` | 小标签、图标底板 |
| `radiusMedium` | `16dp` | 普通卡片、按钮 |
| `radiusLarge` | `20dp` | 推荐问题、业务卡片 |
| `radiusXLarge` | `28dp` | 弹层、大卡片 |
| `radiusPill` | `50%` | 输入框、快捷胶囊 |

同一组件在所有页面必须使用相同圆角，禁止随意混用。

### 6.2 描边

- 默认描边：`1dp / MilingBorder`。
- 聚焦描边：`1.5dp / MilingPrimary`。
- 错误描边：`1.5dp / MilingError`。
- 卡片优先使用描边而不是阴影区分层级。

### 6.3 阴影

整体采用低阴影设计：

| 层级 | Elevation | 用途 |
|---|---:|---|
| `0dp` | 无 | 普通页面和大部分卡片 |
| `2dp` | 极轻 | 浮动提示、小弹层 |
| `6dp` | 轻 | 底部消息输入框 |
| `12dp` | 中 | Modal、侧边抽屉 |

禁止为普通列表项和每张卡片添加明显投影。

## 7. 图标规范

- 使用统一的线性圆角图标体系，优先 Material Symbols Rounded/项目统一矢量图标。
- 默认图标尺寸：`24dp`。
- 小图标：`20dp`；主入口图标：`28dp`。
- 图标点击区域不得小于 `48 × 48dp`。
- 默认线条视觉粗细保持一致，不混用实心、细线和卡通图标。
- 图标按钮必须提供 `contentDescription`。
- 不使用 Emoji 代替功能图标。

## 8. 首页布局

首页采用单列、对话优先布局。

```text
系统状态栏
顶部导航栏
大留白
米灵形象
“我是米灵”
副标题
推荐问题 × 3
安全提示
弹性留白
快捷入口横向列表
底部消息输入框
系统导航栏
```

### 8.1 顶部导航栏

- 左侧：会话抽屉按钮。
- 中间：页面标题“米灵”及声音状态。
- 右侧：钱包/个人入口，具体图标按当前页面语义选择。
- 左、中、右点击区域均为 `48dp`。
- 标题视觉居中，不因两侧图标宽度不同发生偏移。

### 8.2 米灵形象

- 首页形象建议宽高 `104–120dp`。
- 使用原创蓝紫软体/光团形象。
- 可以使用柔和模糊和透明度，但边缘不能脏、灰或过度发光。
- 不使用写实人物头像作为默认米灵形象。
- 米灵动画应非常轻微，不干扰阅读。

### 8.3 推荐问题卡片

- 高度：最小 `72dp`。
- 圆角：`20dp`。
- 描边：`1dp / MilingBorder`。
- 水平内边距：`16dp`。
- 图标底板：`44 × 44dp`，圆角 `12dp`。
- 图标与文字间距：`16dp`。
- 右侧箭头使用 `MilingIconSecondary`。
- 卡片之间间距：`12dp`。
- 一次最多展示三个建议，文案应可直接执行。

推荐文案格式：

- “今天花了多少钱？”
- “帮我给小李转 50 元”
- “分析一下本月账单”

### 8.4 安全提示

- 使用紧凑胶囊卡片。
- 图标和文字同时表达安全含义。
- 推荐文案：“每笔支付都需要你亲自确认”。
- 不使用警告红色；默认使用品牌蓝和中性灰。

### 8.5 快捷入口

- 横向滚动，首屏建议完整显示 3–4 个。
- 高度：`48dp`。
- 左右内边距：`16dp`。
- 圆角：胶囊形。
- 入口之间间距：`10dp`。
- 默认入口：转账、查余额、看账单、生活助手。
- 不使用底部五栏导航与快捷入口重复表达同一功能。

### 8.6 底部消息输入框

- 高度：`72dp`。
- 水平外边距：`20dp`。
- 圆角：`36dp`。
- 背景：`MilingSurface`。
- 描边：`1dp / #E7EAF0`。
- Elevation：`6dp`。
- 左侧语音按钮：`48dp`。
- 右侧相机与更多按钮：各 `48dp`。
- 占位文字使用 `bodyLarge / MilingTextMuted`。
- 输入后，最右侧“更多”可切换为品牌蓝发送按钮。

键盘弹出时：

- 输入框跟随 IME Insets 上移。
- 快捷入口可以隐藏。
- 对话列表保持最后一条消息可见。
- 不允许输入框覆盖支付确认卡。

## 9. 对话与业务卡片

### 9.1 普通消息

- 用户消息靠右，使用 `MilingPrimarySoft`。
- 米灵消息靠左，使用 `MilingSurfaceSubtle` 或无气泡排版。
- 气泡最大宽度：屏幕内容宽度的 `82%`。
- 正文使用 `bodyLarge`。
- 消息时间默认弱化，仅在需要时展示。

### 9.2 AI 工具卡片

余额、账单、收款人和转账准备结果使用结构化卡片，不混入纯文本：

- 卡片标题说明数据来源或业务对象。
- 关键金额使用高对比大字号。
- 状态同时显示图标和文字。
- 主操作放在卡片底部。
- 卡片必须覆盖加载、空、失败、处理中和完成状态。

### 9.3 转账确认卡

转账确认属于高风险组件，必须比普通推荐卡片更明确：

- 显示收款人、金额、备注和资金来源。
- 金额使用 `headlineLarge / Bold`。
- 主按钮使用实心品牌蓝：“确认转账”。
- 次按钮使用文字或描边样式：“取消”。
- 按钮不得预设倒计时自动确认。
- 未获得一次性支付授权时不得展示成功状态。

### 9.4 交易结果

| 状态 | 主色 | 页面操作 |
|---|---|---|
| 成功 | `MilingSuccess` | 查看账单、完成 |
| 处理中 | `MilingProcessing` | 查看详情、返回钱包 |
| 失败 | `MilingError` | 查看原因、返回 |
| 已取消 | `MilingTextSecondary` | 重新发起（创建新意图） |

处理中页面不得提供“再次提交同一笔交易”按钮。

## 10. 登录与验证码页面

登录页延续首页的极简留白：

- 米灵 Logo/形象放在页面中上部。
- 手机号输入和主按钮放在页面下半部。
- 主按钮高度 `52dp`，圆角 `16dp`。
- 输入框高度不低于 `56dp`。
- 区号、手机号、清除按钮有明确区域。
- 协议勾选不得默认选中。

验证码页面：

- 顶部保留返回按钮。
- 标题居中或左对齐，但同一流程保持一致。
- 六位验证码采用系统键盘和自动填充能力。
- 输入框之间保持 `8–12dp` 间距。
- 倒计时结束前“重新发送”保持禁用样式。
- 错误信息在验证码区域附近显示，不只使用 Toast。

## 11. 抽屉与个人中心

### 11.1 会话抽屉

- 从左侧滑入，宽度为屏幕的 `82–88%`。
- 背后蒙层使用黑色 `32%` 透明度。
- 顶部包含新建对话和搜索。
- 会话按“今天、最近一周、更早”分组。
- 当前会话使用 `MilingSurfaceBlue` 高亮。
- 底部固定个人入口和必要状态。

### 11.2 个人中心

- 使用浅灰页面背景和白色分组卡片。
- 列表项高度不低于 `56dp`。
- 图标、标题、当前值、箭头按同一基线排列。
- 分组间距 `16dp`，组内使用弱分割线。
- 支付密码、登录设备和账号安全放入独立“安全”分组。

## 12. 控件状态

所有交互组件必须实现以下状态：

| 状态 | 表现 |
|---|---|
| 默认 | 白色/浅色表面、标准描边 |
| 按下 | `MilingSurfaceBlue`，不改变组件尺寸 |
| 聚焦 | 品牌蓝描边和可见焦点 |
| 选中 | 品牌浅蓝背景 + 品牌蓝图标/文字 |
| 禁用 | 内容透明度约 `38%`，禁止点击 |
| 加载 | 保持原尺寸，显示进度且阻止重复提交 |
| 错误 | 错误色描边 + 就近文字说明 |

按钮按下不得使用会造成布局位移的缩放效果。

## 13. 动效与反馈

| 类型 | 时长 | 建议 |
|---|---:|---|
| 点击反馈 | `100–150ms` | 颜色、透明度变化 |
| 组件切换 | `180–220ms` | 淡入淡出或轻微位移 |
| 页面切换 | `240–300ms` | 平滑、克制 |
| 抽屉 | `260ms` | 标准水平滑入 |

要求：

- 动画优先修改 `alpha` 和 `transform`。
- 米灵形象可以有低频呼吸动画，但幅度不超过 `2–3%`。
- 流式回复使用光标或三点提示，不使用持续旋转的大型装饰动画。
- 成功反馈可配合一次轻震动；失败和高风险操作使用明确反馈。
- 尊重系统“移除动画/减少动态效果”设置。

动画属于 UI 层，不进入 ViewModel；ViewModel 只暴露业务状态。

## 14. 深色模式

选定视觉稿以浅色模式为主。首版必须先保证浅色模式完整一致。

如果启用“跟随系统”：

- 不采用纯黑大面积配高饱和紫色。
- 页面背景建议 `#101217`，Surface 建议 `#181B22`。
- 主文字建议 `#F5F7FA`，次文字建议 `#B6BDC8`。
- 描边建议 `#2A303A`。
- 品牌蓝可以提高亮度，但必须重新检查对比度。
- 不能简单反转图片、图标或语义色。

## 15. 无障碍要求

- 所有可点击区域最小 `48 × 48dp`。
- 图标按钮必须有中文 `contentDescription`。
- TalkBack 顺序应与视觉阅读顺序一致。
- 金额应按完整人民币读法提供语义描述。
- 状态不能仅靠颜色区分。
- 普通文字对比度不低于 `4.5:1`。
- 支持字体缩放和显示大小调整。
- 输入框必须有持久标签或明确语义，不能只依赖占位符。
- 焦点进入高风险确认卡时，先播报收款人、金额和状态，再播报按钮。

## 16. 支付安全界面要求

- 支付密码界面使用系统安全输入法能力。
- 支付密码不写入 Compose State 的可持久化容器。
- 支付密码、验证码和 Token 不进入日志、截图、埋点或 AI 上下文。
- 支付密码页面和敏感结果页应按安全策略启用 `FLAG_SECURE`。
- 所有资金写操作显示提交中状态并禁止重复点击。
- 最终结果以服务器查询结果为准，禁止前端本地推断成功。

## 17. Compose 落地要求

- 所有颜色通过 `MaterialTheme.colorScheme` 或 `MilingColors` 扩展访问。
- 所有文字通过 `MaterialTheme.typography` 访问，禁止业务页面硬编码 `sp`。
- 间距和圆角通过统一 Token 使用。
- `remember` 只保存滚动、展开和动画等 UI 状态。
- 钱包、账单、转账和支付状态由 ViewModel/Repository 提供。
- 页面必须使用 `WindowInsets` 处理状态栏、导航栏和 IME。
- 列表使用稳定 Key，避免流式消息时重复重组和跳动。
- 图标统一使用项目矢量资源或同一套 Material Symbols。

建议 Token 命名：

```kotlin
object MilingSpacing {
    val Xs = 4.dp
    val Sm = 8.dp
    val Md = 12.dp
    val Lg = 16.dp
    val Xl = 20.dp
    val Xxl = 24.dp
    val Section = 32.dp
    val Hero = 64.dp
}

object MilingRadii {
    val Small = 10.dp
    val Medium = 16.dp
    val Large = 20.dp
    val ExtraLarge = 28.dp
}
```

## 18. 禁止项

- 不复制第三方 AI App 的 Logo、头像、名称或原文案。
- 不使用大面积彩色渐变背景。
- 不使用玻璃拟态、强发光、厚重投影。
- 不在首页堆叠多个统计图和营销 Banner。
- 不使用 Emoji 作为功能图标。
- 不允许同一层级出现多种圆角、线宽和图标风格。
- 不使用低对比浅灰展示关键说明。
- 不通过颜色伪装交易已经成功。
- 不把支付密码输入框放进 AI 对话气泡。
- 不允许外卖 WebView 复用或伪装成原生支付确认页。
