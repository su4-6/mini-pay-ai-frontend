# MiniPay Android 个人中心需求文档 v1.0

> 文档状态：需求基线草案  
> 编写日期：2026-08-08  
> 适用端：MiniPay Android  
> 读者：产品、Android、Identity、Agent、Commerce、Payment、Wallet、测试与安全人员

## 1. 文档目的

本文基于当前 Android 源码、前后端契约、数据库迁移、测试、现有原型和架构约束，对个人中心做一次可追踪的现状盘点，并定义后续应交付的完整需求。

本文重点解决以下问题：

1. 区分已经接入、部分接入、产品占位和完全缺失的能力，避免把占位页计为完成。
2. 明确个人中心主页、资料、账号安全、外卖订单、长期记忆、钱包入口、退出与注销的产品规则。
3. 明确 Identity、Agent、Commerce、Payment、Wallet 的数据所有权和协作方式。
4. 为 Android、后端契约、集成测试和验收建立统一追踪基线。

### 1.1 已确认的产品决策

- 个人中心的“订单”仅指外卖订单；支付、转账、充值、提现等资金流水继续由钱包账单承载。
- 外卖订单中心支持完整生命周期动作，包括继续支付、允许阶段取消/退款、状态恢复和再来一单。
- 长期记忆允许用户创建、编辑、删除，支持结构化白名单类型和经过安全审核的通用短文本。
- 账号管理保留手机号和邮箱，并新增短信验证后的支付密码修改；登录设备管理不在本期。
- 应用授权管理本期继续展示固定空态，不新增真实授权接口，也不计为功能缺失。
- 注销申请和撤销均使用当前手机号短信验证；存在未完成外卖订单时阻断注销。
- 关闭记忆总开关只停用记忆，不删除已有数据；一键清空是独立的破坏性操作。
- 银行卡管理继续从钱包进入，不在个人中心新增直达入口。

## 2. 基线与约束

### 2.1 分析基线

| 基线 | 用途 |

| `android/app/src/main/java/com/minipay/mobile/profile/*` | 资料模型、头像处理、Repository 与 ViewModel |
| `android/app/src/main/java/com/minipay/mobile/MiniPayApp.kt` | 个人中心导航与钱包路由 |
| `android/app/src/androidTest/.../ProfileScreenTest.kt` | 现有个人中心 Compose 测试 |
| `android/app/src/test/.../ProfileValidationTest.kt` | 现有昵称校验测试 |
| `contracts/openapi/identity-api-v1.yaml` | Identity 当前公开契约 |
| `services/identity-service` | 资料、账号安全、支付密码当前实现 |
| `services/agent-service` | 当前聊天骨架；尚无长期记忆实现 |
| `services/commerce-service` | 当前仅有服务和技术消息表骨架 |
| `docs/prototypes/米灵个人中心.png` 等 | 视觉与信息架构参考，不覆盖本文业务规则 |

### 2.2 强制架构约束

- Identity 独占消费者资料、联系方式、登录凭据、支付密码凭据和注销状态。
- Agent 独占 AI 长期记忆；不得直接访问 Identity、Commerce、Payment 或 Wallet 数据库。
- Commerce 独占商家、商品、购物车、地址、外卖订单和履约状态；不得修改支付状态或钱包余额。
- Payment 独占支付、退款、转账、充值、提现等资金订单状态；Wallet 独占余额和复式账本。
- 服务之间只允许通过版本化 API、可靠事件或既定 TCC 分支协议协作，禁止跨服务数据库查询或写入。
- 外卖订单与支付、注销限制传播使用本地事务加 Outbox/Inbox 和幂等状态机，不使用长事务 TCC。
- 金额以人民币分的 `long/BIGINT` 表示；时间使用 UTC `Instant/DATETIME(6)`，API 使用 ISO-8601。
- Android 不保存或记录完整 Token、验证码、支付密码、完整银行卡、完整地址等敏感数据。

### 3.2 已确认的关键缺陷

#### DEF-PC-001 更换手机号后会话未失效

当前手机号换绑成功页只提示“请使用新手机号重新登录”，点击完成会返回上一页。Android 没有调用会话清理，Identity 也没有撤销当前 Refresh Token family。该行为与“手机号更换后强制 Android 丢弃本地会话”的安全约束不一致。

期望：手机号更新事务成功后，Identity 撤销当前用户的 Refresh Token family；Android 无论服务端注销调用是否成功，都必须清除本地 Access Token、Refresh Token、用户标识和用户级缓存并返回登录页。

#### DEF-PC-002 账号管理表单和验证码流程不完整

- 手机号和邮箱仅以非空判断启用提交，未执行本地格式校验。
- 验证码页没有限制 6 位数字，确认按钮仍显示“获取验证码”。
- 没有展示挑战有效期、60 秒重发倒计时、最多 5 次失败和 10 分钟锁定。
- 网络、令牌失效、验证码错误/过期、限流等均退化为通用错误。
- 邮箱删除点击后直接调用后端，没有二次确认。

#### DEF-PC-003 昵称规则说明与实现不一致

目标规则和实际校验均为中文、字母、数字或下划线，2～20 个 Unicode 码点，不允许减号；编辑页辅助文案却写为“支持中文、数字、下划线或减号”。文案必须修正，并合并重复校验实现，避免规则漂移。

#### DEF-PC-004 契约与自动化测试不足

Identity 已实现账号安全 Controller，但相应路径、DTO、scope、错误码和响应尚未进入 `identity-api-v1.yaml`。Android 仅有个人中心两项 Compose 测试和昵称校验测试，账号安全、订单、记忆、注销均无覆盖。

## 4. 产品目标与范围

### 4.1 目标

1. 让用户从个人中心安全地管理资料、联系方式和支付密码。
2. 提供不依赖 AI 的确定性外卖订单查询和处置入口。
3. 让用户对 AI 长期记忆拥有明确、可见、可修改、可停用和可删除的控制权。
4. 提供满足资金一致性、履约一致性和数据保留要求的账号注销闭环。
5. 所有页面覆盖正常、加载、空数据、失败、无权限、限流、处理中和恢复状态。

### 4.2 本期不包含

- 登录设备或会话设备列表、单设备下线、其他设备全部退出。
- 真实第三方应用授权列表、授权同意页或授权撤销。
- 从个人中心直接进入银行卡管理。
- 在外卖订单中心展示支付、转账、充值和提现订单。
- 使用 AI 直接执行订单取消、退款、记忆保存或账号注销。
- Android 直接修改 Payment、Wallet 或 Commerce 的权威状态。

导航要求：

- 每个二级页面必须有独立稳定路由，禁止继续复用 `profile/feature/{feature}` 占位路由承载真实业务。
- 返回时保留订单筛选、列表位置和未提交表单草稿；包含敏感输入的草稿不得持久化。
- 更换手机号、退出登录或注销完成引发会话清理后，清空整个已认证导航栈。
- 冷静期用户登录后进入受限主页，个人中心固定展示注销状态和撤销入口。

## 6. 详细功能需求

### 6.1 PC-001 个人中心主页

#### 展示

- 顶部展示头像、昵称、MiniPay 号和“编辑资料”提示。
- 功能顺序固定为：账号管理、应用授权管理、钱包、订单、记忆、退出登录、注销账号。
- “注销账号”使用危险色；其他项目不得仅靠颜色表达状态。
- 应用授权管理进入固定空态，不发起网络请求。

#### 状态

- 首次进入且无缓存时展示保持布局稳定的加载状态。
- 已有成功资料时，前台刷新不得用全屏加载覆盖旧数据；刷新失败展示非阻断提示并允许重试。
- Token 无效时统一清除会话并返回登录页，不在页面内循环重试。
- 头像加载失败或 URL 过期时展示默认头像；回到前台后刷新资料以获取新的临时 URL。

#### 验收标准

- AC-PC-001：从首页和会话抽屉均可进入个人中心，返回路径正确。
- AC-PC-002：资料加载成功时展示真实昵称、头像和 MiniPay 号，不使用演示默认值覆盖服务端数据。
- AC-PC-003：订单和记忆不再进入占位页；应用授权管理仍只展示确认过的空态。
- AC-PC-004：触控项高度不小于 56dp，语义角色和 TalkBack 名称完整。

### 6.2 PC-002 编辑个人信息

#### 昵称

- 长度为 2～20 个 Unicode 码点。
- 仅允许中文、Unicode 字母、数字和下划线，不允许空格、减号和其他标点。
- 输入时显示实时计数；非法原因在输入框附近展示并可被 TalkBack 播报。
- 保存前去除首尾空白；由于空白本身不合法，修剪不得使原非法值静默通过。
- MiniPay 号只读，不允许复制成可编辑字段。

#### 头像

- 使用系统图片选择器，不申请不必要的全量媒体权限。
- Android 将图片居中裁切为正方形，最长边不超过 1024px，转换为 JPEG，大小不超过 5MiB，并计算 SHA-256。
- Android 先向 Identity 申请用户绑定、短时有效、对象键不可自选的上传凭证，再直传私有 OSS。
- Identity 校验对象元数据和内容安全结果后，才在资料更新事务中替换头像引用。
- 上传或审核失败时保留昵称草稿和本地选择预览，并提供“重新上传”或“重新选择”。
- 当前版本只支持替换头像，不提供删除头像操作。

#### 并发与离开

- 更新携带资料版本号；发生 `PROFILE_VERSION_CONFLICT` 时不得覆盖他端修改，应提示返回刷新后重试。
- 有未保存修改时，系统返回键和顶部返回键均弹出放弃确认。
- 保存期间禁用返回、头像选择和重复提交；按钮尺寸不得因进度指示器变化。

#### 验收标准

- AC-PC-005：客户端与服务端对昵称规则的判断一致，辅助文案不再提及减号。
- AC-PC-006：头像选择、处理、直传、审核、提交任一步失败均可恢复，不出现半更新资料。
- AC-PC-007：连续点击保存只产生一个资料更新请求。
- AC-PC-008：版本冲突不会覆盖服务端新版本资料。

### 6.3 PC-003 账号管理

#### 6.3.1 概览

展示以下信息：

- 当前绑定手机号，仅展示脱敏值。
- 邮箱状态：未绑定或脱敏邮箱。
- 支付密码状态：已设置；不得展示、缓存或返回密码摘要。

页面加载失败时提供重试；部分字段不得以“已绑定”等模糊默认值替代真实响应。

#### 6.3.2 更换手机号

1. 输入新的中国大陆手机号，必须满足 `^1[3-9]\d{9}$`，且不能与当前手机号相同。
2. 请求发送短信验证码；响应展示脱敏新手机号、有效期和重发等待秒数。
3. 验证码为 6 位数字；60 秒内禁用重发，最多验证 5 次，超限锁定 10 分钟。
4. 验证成功后 Identity 原子更新手机号，并撤销当前 Refresh Token family。
5. Android 收到成功后立即清除本地会话和全部用户级缓存，返回手机号登录页；不得先返回个人中心。

验证码挑战必须绑定：当前用户、新手机号、用途 `PHONE_CHANGE`、挑战 ID 和有效期；不可用于登录、支付密码修改或注销。

#### 6.3.3 邮箱绑定、更换和删除

- 邮箱先规范化再校验，最大 254 字符；不允许只依赖占位文案作为标签。
- 验证码挑战绑定当前用户、目标邮箱和用途 `EMAIL_BIND`，并具备有效期、次数限制和重发限制。
- 绑定或换绑成功后刷新账号概览。
- 删除邮箱前展示二次确认，说明邮箱不作为 Android 登录方式；确认后才发送删除请求。
- 邮件服务不可用时失败关闭，不得绕过验证直接绑定。

#### 6.3.4 修改支付密码

1. 先向当前手机号发送用途为 `PAYMENT_PASSWORD_CHANGE` 的短信验证码。
2. 短信验证成功后签发最长 5 分钟、单次使用、绑定当前用户和设备的验证凭据。
3. 用户输入并再次确认新的 6 位数字支付密码；输入框禁复制、禁明文回显，页面启用安全窗口防截屏。
4. 两次输入一致且验证凭据有效时提交修改；Identity 使用 Argon2id 强哈希覆盖原凭据。
5. 成功后撤销尚未消费的一次性支付授权；不强制退出登录。
6. 新密码不得进入日志、埋点、SavedStateHandle、导航参数或持久化存储。

#### 账号管理验收标准

- AC-PC-009：手机号、邮箱和验证码在客户端完成明确格式校验，服务端仍执行权威校验。
- AC-PC-010：验证码页按钮文案分别为“获取验证码”“确认更换/绑定”，支持倒计时和重发。
- AC-PC-011：更换手机号成功后无法通过返回键回到已认证页面，本地安全存储已清空。
- AC-PC-012：邮箱删除必须二次确认，失败时仍保留原邮箱展示。
- AC-PC-013：修改支付密码必须完成当前手机号验证，验证凭据不可跨用途、跨用户或重复使用。

### 6.4 PC-004 应用授权管理

- 保留入口和页面标题。
- 页面固定展示“暂未接入可授权的外部平台。”。
- 不展示伪造的授权记录，不调用不存在 API，不把固定空态当成网络空数据。
- 后续真实授权能力必须另行评审 OAuth 授权、scope 展示、撤销影响和审计规则，不包含在本文交付范围。

### 6.5 PC-005 钱包入口

- 点击“钱包”继续进入既有 `FinanceDestination.WALLET`。
- 余额、银行卡、充值、提现和资金账单的权威规则仍由 Finance 模块及对应服务负责。
- 个人中心不得缓存或乐观修改余额，也不得新增银行卡直达入口。

### 6.6 PC-006 外卖订单列表

#### 查询范围

- 只查询当前登录用户的 Commerce 外卖订单。
- 默认按 `createdAt` 倒序，默认每页 20 条，最大每页 50 条。
- 支持按状态分组筛选：全部、待付款、进行中、已完成、已取消/退款。
- 支持按完整或部分订单号、商家名称、商品名称搜索；输入最大 50 字符并防抖，不提供跨用户查询。
- 下拉刷新重置到第一页；加载更多复用当前筛选和搜索条件。

#### 列表项

每个订单至少展示：

- 订单号、商家名称、订单状态和创建时间。
- 最多两项商品缩略信息，超过时显示总件数。
- 权威订单总金额，接口使用分，Android 只格式化展示。
- 当前允许的主动作，例如“继续支付”“查看配送”“再来一单”。

#### 页面状态

- 首屏加载、加载更多、筛选空态、搜索无结果、网络失败和登录失效必须分别处理。
- 加载更多失败保留已有列表并提供行内重试。
- 订单状态以查询 API 为准；推送或事件只触发精确刷新，不直接修改为终态。

#### 验收标准

- AC-PC-014：列表只返回当前用户订单，分页无重复、无遗漏，筛选和搜索条件可组合。
- AC-PC-015：金额从整数分格式化，不使用浮点数参与计算。
- AC-PC-016：空态、首屏失败和加载更多失败不会互相混淆。
- AC-PC-017：返回订单详情后保留筛选条件和滚动位置。

### 6.7 PC-007 外卖订单详情与动作

#### 订单状态与允许动作

| 状态 | 用户文案 | 允许动作 |
|---|---|---|
| `PENDING_PAYMENT` | 待付款 | 继续支付、取消订单 |
| `PAID` | 已付款，等待商家接单 | 查看、取消并申请全额退款 |
| `ACCEPTED` | 商家已接单 | 查看；P0 不允许用户主动取消 |
| `PREPARING` | 制作中 | 查看 |
| `DELIVERING` | 配送中 | 查看模拟配送进度 |
| `DELIVERED` | 已送达 | 查看、再来一单 |
| `CANCELLED` | 已取消 | 查看取消原因、可用时再来一单 |
| `REFUND_PROCESSING` | 退款处理中 | 查询恢复，不得重复申请 |
| `REFUNDED` | 已全额退款 | 查看退款结果、可用时再来一单 |
| `REFUND_FAILED` | 退款处理异常 | 查询最新结果和安全说明；不得创建第二笔退款 |

#### 详情展示

- 商家、商品、规格、数量、商品金额、配送费、优惠、应付金额和币种。
- 脱敏收货人、手机号和配送地址。
- 下单、支付、接单、制作、配送、送达、取消和退款等已有时间节点。
- 支付状态、退款状态和安全失败说明；不展示内部异常、通道报文或凭据。
- 服务端返回 `allowedActions`，Android 不自行推导越权动作，但必须对未知动作安全忽略。

#### 继续支付

- 只对未过期的 `PENDING_PAYMENT` 订单开放。
- Android 进入原生支付确认流程，并重新查询权威金额和可用渠道。
- 同步返回不得直接视为成功；`PROCESSING` 进入查询恢复，不重复创建支付单。

#### 取消与退款

- 待付款取消无需退款，但必须二次确认。
- `PAID` 且尚未接单时，可二次确认后提交取消请求；Commerce 记录请求并通过可靠协作向 Payment 请求全额退款。
- 退款处理中只允许查询；相同订单和取消请求的重试复用幂等键。
- Android 不直接调用 Wallet，不直接修改订单或支付状态。

#### 再来一单

- 再来一单只创建当前用户可复核的购物车草稿，不直接创建订单或支付。
- Commerce 重新校验商家营业状态、配送范围、商品、规格、库存和当前价格。
- 对停售、售罄、规格失效、价格或优惠变化逐项提示；用户确认新购物车和报价后才能结算。
- 原订单中的收货地址只按地址 ID 引用，不把完整地址写入 Agent 记忆或日志。

#### 验收标准

- AC-PC-018：不同状态只展示服务端允许动作，未知状态降级为只读详情。
- AC-PC-019：取消、退款和继续支付均防止重复提交，处理中状态可在重启后恢复。
- AC-PC-020：再来一单不静默替换商品、规格或价格，不自动提交订单。
- AC-PC-021：订单列表和详情的状态最终与 Commerce 权威状态一致。

### 6.8 PC-008 长期记忆

#### 记忆类型

| 类型 | 稳定枚举 | 输入与存储规则 |
|---|---|---|
| 餐饮偏好 | `FOOD_PREFERENCE` | 例如口味、常点品类；文本不超过 200 个 Unicode 码点 |
| 忌口/过敏原 | `DIETARY_RESTRICTION` | 用户明确输入；下单仍需再次核对，不作为医疗事实 |
| 预算习惯 | `BUDGET_PREFERENCE` | 结构化金额使用分，可附不超过 200 字说明 |
| 联系人别名 | `CONTACT_ALIAS` | 保存别名和联系人 ID，不保存完整手机号或实名 |
| 常用地址引用 | `ADDRESS_REFERENCE` | 保存别名和 Commerce 地址 ID，不保存完整地址正文 |
| 通用短文本 | `GENERAL_TEXT` | 不超过 200 个 Unicode 码点，必须通过类型和内容安全校验 |

#### 禁止保存

- 完整手机号、完整地址、身份证件、银行卡号、完整实名或人脸材料。
- 登录密码、支付密码、验证码、Token、Cookie、密钥或支付授权。
- 余额、账单明细、具体交易历史或信用推断。
- 未经用户确认由模型推断出的健康、宗教、政治等敏感属性。
- 任何绕过白名单、长度限制或内容安全规则的自由文本。

#### 总开关

- 默认值由服务端返回，不由 Android 猜测。
- 关闭后立即停止新记忆创建和 AI 检索，现有记忆保留并仍可在管理页查看、编辑或删除。
- 重新开启后，仍为 `ACTIVE` 且引用有效的记忆恢复参与检索。
- 开关写操作幂等，失败时回滚 UI，不做乐观持久化。

#### 创建与编辑

- 用户可从个人中心手工创建，也可在 AI 对话确认卡中明确点击“记住”后创建。
- 创建页先选择类型，再展示相应字段；联系人和地址必须使用受控选择器返回资源 ID。
- 编辑只允许修改可展示内容、别名、结构化值或引用，不允许改变资源所有权。
- Agent 对资源 ID 做当前用户所有权校验；引用失效时标记 `INVALID_REFERENCE` 并提示重新选择。
- 所有写操作使用 `Idempotency-Key`；相同键参数冲突返回稳定错误。

#### 删除与清空

- 单条删除需要二次确认，成功后立即从后续 AI 检索排除。
- 一键清空必须单独二次确认，并明确“不影响聊天、订单、支付、账本和审计记录”。
- 删除采用幂等逻辑删除；重复请求返回相同结果，不恢复已删除记忆。

#### 列表与状态

- 默认按更新时间倒序，默认每页 20 条，最大每页 50 条，可按类型筛选。
- 列表展示类型、可安全展示的内容、来源、创建/更新时间和引用状态。
- 页面覆盖加载、空态、加载更多失败、内容被拒绝、引用失效、限流和无权限。

#### 验收标准

- AC-PC-022：关闭总开关后，新的对话运行不能检索或创建记忆，已有记忆未被删除。
- AC-PC-023：禁止内容无法保存，也不会进入日志、工具 Trace 或模型上下文。
- AC-PC-024：记忆只能由本人查询和修改；伪造联系人/地址 ID 返回统一所有权错误。
- AC-PC-025：删除或清空成功后，后续检索立即排除对应记录。
- AC-PC-026：通用文本按 Unicode 码点限制 200 字，Android 与服务端结果一致。

### 6.9 PC-009 退出登录

- 点击“退出登录”先展示二次确认。
- 确认后尝试撤销 Refresh Token；无论网络调用成功与否，Android 都清除本地安全存储、用户级缓存和已认证导航栈。
- 退出不删除资料、订单、记忆、钱包或账本数据。
- 退出请求期间禁用重复点击；不得记录 Refresh Token 或 Authorization 头。

### 6.10 PC-010 账号注销

#### 6.10.1 资格检查

Identity 负责聚合注销资格，但不得查询其他服务数据库。它通过版本化内部 API 查询 Wallet、Payment 和 Commerce，返回统一的可展示阻断原因。

必须同时满足：

- 用户为正常活动状态，且当前没有另一条冷静期注销记录。
- Wallet 可用余额、冻结金额、待入账和其他预留均为零。
- Payment 不存在处理中的转账、充值、提现、支付或退款。
- Commerce 不存在 `PENDING_PAYMENT`、`PAID`、`ACCEPTED`、`PREPARING`、`DELIVERING`、`REFUND_PROCESSING` 或尚未收束的 `REFUND_FAILED` 订单。

资格页按领域展示阻断原因和可行动入口，例如“前往钱包”“查看处理中订单”“查看外卖订单”。不得只展示通用“不可注销”。

#### 6.10.2 提交申请

1. 用户阅读注销影响并主动勾选确认。
2. 向当前手机号发送用途为 `ACCOUNT_CANCELLATION_SUBMIT` 的短信验证码。
3. 验证码校验成功后，Identity 再次实时查询全部资格，防止首次检查后的竞态。
4. 通过后创建唯一的 `PENDING_COOLING_OFF` 注销记录，冷静期为 7×24 小时。
5. Identity 在同一本地事务写注销记录与 Outbox，并撤销当前 Refresh Token family。
6. Android 清除当前会话；用户再次短信登录时进入受限模式。

#### 6.10.3 冷静期限制

- 禁止新建支付、转账、充值、提现、外卖订单、结算和新记忆。
- 允许查看资料、钱包、资金账单、历史外卖订单和记忆。
- 允许完成必要的订单取消、退款查询与系统发起的资金冲正。
- Payment、Wallet、Commerce 和 Agent 消费账户限制事件，在各自写入口二次校验；仅隐藏 Android 按钮不构成安全控制。
- 个人中心固定展示冷静期结束时间和“撤销注销”入口。

#### 6.10.4 撤销注销

- 撤销需要当前手机号、用途为 `ACCOUNT_CANCELLATION_REVOKE` 的新短信验证码。
- 验证成功后 Identity 幂等撤销待处理记录，并通过 Outbox 发布解除限制事件。
- 各服务幂等消费后恢复正常写入；Android 刷新账户能力状态。

#### 6.10.5 到期完成

- 到期任务获取租约后再次查询 Wallet、Payment、Commerce 资格；失败时进入 `COMPLETION_BLOCKED`，保留原因并重试，不直接修改其他服务数据。
- 最终完成时，Identity 在本地事务匿名化昵称、头像和联系方式，禁用登录与支付凭据并写 Outbox。
- Agent 删除或不可逆匿名化长期记忆和用户可识别会话资料；Commerce 保留订单业务事实但匿名化非必要个人资料。
- Wallet 账本、Payment 资金订单、Commerce 法定/审计订单引用和登录审计按制度保留，不允许删除账本分录或改写已完成交易。

#### 注销验收标准

- AC-PC-027：任一服务返回阻断条件时无法提交注销，页面显示稳定、安全、可行动的原因。
- AC-PC-028：资格首次通过后并发创建资金或外卖订单时，第二次检查或写入口限制必须使一方失败，不出现注销与新交易同时成功。
- AC-PC-029：冷静期内所有新资金和新外卖写入口均被服务端阻断，查询、取消和退款恢复仍可用。
- AC-PC-030：撤销需要独立短信挑战，重复撤销幂等。
- AC-PC-031：到期匿名化不删除或修改账本、已完成支付、退款和订单业务事实。

### 6.11 PC-011 通用页面状态、交互与可访问性

所有页面必须实现：

| 状态 | 要求 |
|---|---|
| 加载 | 保持布局稳定；提交控件原尺寸显示进度并禁用重复点击 |
| 空数据 | 说明空的原因和下一步；授权固定空态与网络空态分开 |
| 网络失败/超时 | 保留安全草稿和已有数据，提供明确重试入口 |
| 401 | 清除无效会话并返回登录页 |
| 403 | 显示无权限，不重复发请求 |
| 409 | 按稳定 `code` 处理版本或状态冲突，并提供刷新动作 |
| 422 | 在对应字段附近显示校验原因 |
| 429 | 展示可重试时间；倒计时期间禁用提交 |
| 502/503 | 展示依赖暂不可用并允许安全重试，不把失败当成功 |
| 处理中 | 查询权威状态；不得重新创建相同订单、退款或注销申请 |

可访问性与布局要求：

- 支持最小宽度 320dp、系统字体放大和横竖屏安全区域，不出现水平滚动或操作按钮被系统栏遮挡。
- 图标按钮、列表项和主要控件触控区域不小于 48×48dp；列表项高度不小于 56dp。
- 所有图标按钮具备明确 `contentDescription`；装饰图标从语义树隐藏。
- 输入框有持久标签；错误使用可播报的语义，不只依赖红色。
- 焦点顺序与视觉顺序一致；键盘操作完成后焦点移动到错误或结果区域。
- 动效尊重系统“减少动态效果”，不使用改变控件尺寸的缩放反馈。

## 7. 目标接口与服务边界

以下为需求级目标契约。实现前必须更新对应 OpenAPI/事件 Schema 并完成兼容性评审；“新增”不代表接口当前已存在。

### 7.1 Identity 公共 API

| 能力 | 建议方法与路径 | scope | 当前状态 | 关键规则 |
|---|---|---|---|---|
| 查询/更新资料 | `GET/PATCH /api/v1/users/me` | `identity.profile.read/write` | 已实现并有 OpenAPI | 版本控制、内容安全 |
| 申请头像上传 | `POST /api/v1/users/me/avatar-uploads` | `identity.profile.write` | 已实现并有 OpenAPI | 用户绑定、短时、私有对象 |
| 查询账号安全 | `GET /api/v1/users/me/account-security` | `identity.security.read` | 已实现，缺 OpenAPI | 仅脱敏联系方式和能力状态 |
| 手机换绑挑战 | `POST /api/v1/users/me/phone-change-challenges` | `identity.security.write` | 已实现，缺 OpenAPI | 绑定用户、手机号、用途 |
| 确认手机换绑 | `PUT /api/v1/users/me/phone` | `identity.security.write` | 已实现，缺会话撤销 | 成功后撤销当前 Token family |
| 邮箱挑战 | `POST /api/v1/users/me/email-verification-challenges` | `identity.security.write` | 已实现，缺 OpenAPI | 限次、限流、用途绑定 |
| 绑定/删除邮箱 | `PUT/DELETE /api/v1/users/me/email` | `identity.security.write` | 已实现，缺 OpenAPI | 幂等、邮箱唯一性 |
| 支付密码修改挑战 | `POST /api/v1/users/me/payment-password-change-challenges` | `identity.security.write` | 新增 | 当前手机、设备、用途绑定 |
| 提交支付密码修改 | `POST /api/v1/users/me/payment-password-changes` | `identity.security.write` | 新增 | 验证凭据单次使用，密码 writeOnly |
| 查询当前注销 | `GET /api/v1/account-cancellations/current` | `identity.account.read` | 新增 | 返回资格/冷静期/阻断原因 |
| 提交注销 | `POST /api/v1/account-cancellations` | `identity.account.write` | 新增 | 短信验证、幂等、二次资格检查 |
| 撤销注销 | `POST /api/v1/account-cancellations/current/revocations` | `identity.account.write` | 新增 | 独立短信挑战、幂等 |

所有写接口必须发送 `X-Request-Id`；具备重试可能的资源创建和状态变更必须使用 `Idempotency-Key`。错误统一采用 RFC 9457 Problem Details，Android 只解析稳定 `code`。

### 7.2 Agent 记忆 API

| 方法与路径 | 能力 | 规则 |
|---|---|---|
| `GET /api/v1/agent/memories` | 记忆分页与类型筛选 | 只查当前用户，最大每页 50 |
| `POST /api/v1/agent/memories` | 手工或确认式创建 | 类型白名单、内容审核、幂等 |
| `PATCH /api/v1/agent/memories/{memoryId}` | 编辑内容或引用 | 所有权与版本校验 |
| `DELETE /api/v1/agent/memories/{memoryId}` | 删除单条 | 幂等逻辑删除，立即排除检索 |
| `DELETE /api/v1/agent/memories` | 一键清空 | 幂等，不影响其他领域事实 |
| `GET/PUT /api/v1/agent/memory-settings` | 查询/更新总开关 | 关闭后停新增与检索，保留数据 |

建议 scope：`agent.memory.read`、`agent.memory.write`；Token audience 为 Android 可用的 Agent 公共受众。记忆 DTO 不得包含联系方式正文、地址正文、凭据或模型内部提示。

### 7.3 Commerce 外卖订单 API

| 方法与路径 | 能力 | 规则 |
|---|---|---|
| `GET /api/v1/commerce/orders` | 当前用户订单分页、筛选、搜索 | 用户所有权、默认 20/最大 50 |
| `GET /api/v1/commerce/orders/{orderId}` | 详情、轨迹、允许动作 | 返回 `allowedActions` 和脱敏配送信息 |
| `POST /api/v1/commerce/orders/{orderId}/cancellation-requests` | 待付款取消或已付款取消退款 | 幂等；Commerce 记录请求后可靠协作 Payment |
| `POST /api/v1/commerce/orders/{orderId}/reorder-drafts` | 生成再来一单购物车草稿 | 重新校验商家、商品、规格、库存和价格 |

建议 scope：`commerce.order.read`、`commerce.order.write`。Commerce 不返回 Payment 内部通道报文，也不接受 Android 传入权威金额或订单所属用户 ID。

### 7.4 注销内部协作

Wallet、Payment、Commerce 分别提供版本化的内部注销资格查询，只返回当前阻断事实和稳定原因，不暴露领域数据库明细。Identity 以 Client Credentials 和专用 scope 调用，例如：

- `wallet.account-cancellation-eligibility.read`
- `payment.account-cancellation-eligibility.read`
- `commerce.account-cancellation-eligibility.read`

Identity 在本地事务写注销状态和 Outbox，发布以下版本化事件：

- `identity.account-cancellation.restricted`
- `identity.account-cancellation.revoked`
- `identity.account-cancellation.completed`

事件信封必须包含 `eventId`、`eventType`、`aggregateType`、`aggregateId`、`occurredAt`、`traceId`、`payloadVersion` 和 `payload`。消费者先以 `eventId` 写 Inbox，再在同一本地事务推进限制投影；重复事件必须安全幂等。

### 7.5 外卖订单与资金协作

- Commerce 创建并维护外卖订单及取消请求；Payment 创建并维护支付/退款单；Wallet 只处理余额和账本。
- 支付、退款结果通过 Outbox/Inbox 事件关联外卖订单，至少一次投递，按 `eventId` 和业务唯一键幂等。
- Commerce 不直接修改 Payment 状态，Payment 不直接修改 Commerce 订单。
- 退款失败或结果不确定保持可恢复状态，禁止直接修余额或修改已完成账务事务。

## 8. 目标数据与状态

### 8.1 记忆最小数据

记忆记录至少包含：`memoryId`、`userId`、`type`、安全展示内容、可选引用 ID、`source`、`status`、`version`、`createdAt`、`updatedAt`、`deletedAt`。通用文本保存内容安全过滤后的值；禁止在字段中保存完整联系人或地址副本。

记忆设置至少包含：`userId`、`enabled`、`version`、`updatedAt`，用户唯一。

### 8.2 注销状态

| 状态 | 含义 | 允许迁移 |
|---|---|---|
| `ELIGIBLE` | 即时资格查询通过，尚未申请 | `PENDING_COOLING_OFF` |
| `INELIGIBLE` | 存在阻断原因 | 条件消除后重新检查 |
| `PENDING_COOLING_OFF` | 7 天冷静期中 | `REVOKED`、`COMPLETED`、`COMPLETION_BLOCKED` |
| `REVOKED` | 用户短信验证后撤销 | 终态；以后可重新申请 |
| `COMPLETION_BLOCKED` | 到期复核仍有阻断 | 条件消除后重试完成 |
| `COMPLETED` | 已匿名化并停止登录 | 终态 |

同一用户最多存在一条活动中的注销记录；状态迁移使用乐观锁和数据库唯一约束。已完成记录不得物理删除。

## 10. 安全、隐私与非功能要求

### 10.1 安全与隐私

- Access Token 校验签名、issuer、audience、过期时间和 scope；用户 Token 与服务 Token 不互相替代。
- 支付密码只进入 Identity；Commerce、Payment、Wallet、Agent 和 Android 持久化层不得保存密码。
- 验证码和短信验证凭据按用途、用户、目标、设备和有效期绑定，只能使用一次。
- 列表、详情、记忆和注销资源全部按 JWT subject 执行所有权校验，不能依赖 Android 隐藏入口。
- 日志、Trace、崩溃上报和埋点不得包含完整手机号、邮箱、地址、验证码、密码、Cookie、Authorization 头、Token、订单配送正文或记忆自由文本。
- 账号注销完成后保留资金和订单业务事实，但删除或匿名化非必要个人资料；不可删除账本或篡改历史交易。

### 10.2 性能与可靠性

- 个人中心和账号概览首屏目标 P95 不高于 1 秒（不含用户网络异常）；列表首屏目标 P95 不高于 1.5 秒。
- 搜索输入防抖 300ms；分页请求串行化，重复条件只保留一个进行中请求。
- GET 可对网络错误和 5xx 最多安全重试一次；写请求只有在复用原幂等键时才允许重试。
- 订单、退款和注销 `PROCESSING` 状态采用 1s、2s、3s、5s 退避，30 秒后停止自动轮询并保留手动刷新。
- 应用进程重启后，从服务端恢复订单、记忆设置和注销状态，不以端侧临时状态作为业务真相。
